# Persistent TV Display Runtime

## Outcome

A TV opens `https://tv.axoboard.io` (or `/tv` on the primary app), enters an eight-character code generated by an AxoBoard administrator, and stays paired through an HttpOnly one-year device cookie. Administrators can name the screen, assign the full dashboard or selected KPIs, change rotation timing, and revoke access immediately.

The TV surface is customer-white-labeled. AxoBoard branding remains on the authenticated administration surface only.

## Runtime flow

1. An authenticated workspace administrator creates a pending display and receives a one-time code valid for ten minutes.
2. The TV exchanges that code for a random device token. Only an HMAC digest is stored in Postgres.
3. The browser receives `axo_display` as `HttpOnly`, `SameSite=Lax`, and `Secure` on HTTPS.
4. The player requests its assigned customer brand, dashboard layout, and certified KPI snapshot.
5. Configuration changes are picked up on the next 45-second refresh. Revocation invalidates the token immediately.
6. The player keeps a 24-hour last-known-good snapshot for short network interruptions and clears it when the server reports that the device is no longer paired.

## Configuration

```env
AXOBOARD_DISPLAY_RUNTIME_ENABLED=true
AXOBOARD_DISPLAY_BASE_URL=https://tv.axoboard.io
AXOBOARD_DISPLAY_TOKEN_SECRET=<independent random secret, at least 32 characters>
```

`AXOBOARD_DISPLAY_TOKEN_SECRET` falls back to `AXOBOARD_OAUTH_ENCRYPTION_KEY` to avoid a deployment hard stop, but production should use an independent secret. Set `AXOBOARD_DISPLAY_RUNTIME_ENABLED=false` for an emergency logical rollback; additive migration `012_persistent_display_devices.sql` can remain in place.

## Domain setup

The server already routes a request with host `tv.axoboard.io` and path `/` to the anonymous TV player. Production still requires:

1. Add `tv.axoboard.io` as a custom domain on the AxoBoard web service.
2. Add the DNS record supplied by the hosting provider.
3. Wait for TLS issuance, then verify `https://tv.axoboard.io`, pairing, refresh persistence, and revocation.

Until DNS is active, the same runtime is available at `https://axoboard.io/tv`.

## Operations and detection

- A display is online when its last heartbeat is under 90 seconds old.
- Pairing is rate-limited to 20 attempts per source over ten minutes.
- Codes exclude ambiguous characters, expire after ten minutes, and are consumed once.
- Workspace IDs scope every administrator list, update, KPI assignment, and revoke query.
- A revoked device never receives customer data; its cached snapshot is removed when unpaired status is confirmed.

## Primary failure modes

1. **TV shows the pairing screen after setup:** check the browser accepts cookies and confirm the display is `active` in Admin → TV displays.
2. **TV stays on cached data:** check network access to `/api/display/runtime`; the player labels the snapshot offline and retries every 45 seconds.
3. **Dedicated hostname fails while `/tv` works:** verify the custom-domain DNS target and TLS state. This is hosting/DNS, not pairing-state failure.
